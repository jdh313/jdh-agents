# Upstream divergences — to-questionnaire

_Upstream: `mattpocock/skills` · `skills/productivity/to-questionnaire` · ledger current as of `reviewed_sha: 321658273cb1`_

Intentional divergences from upstream. First intake reviewed via `skillsmith:upstream-review` (2026-08-29) — do not re-flag these as findings. Read by `upstream-review` only; never referenced from `SKILL.md`.

Upstream's skill is short and almost entirely portable: the three-step send interview, the "grill the send, not the subject" rule, and the `<questionnaire-template>` block are kept **verbatim in substance**, including the worked question example and the answer-stub convention. The divergences below are all at the edges — where the file lands, and what happens after it is answered.

| Kind | What | Why |
|------|------|-----|
| changed | **Invocation policy.** Upstream sets `disable-model-invocation: true` in frontmatter and `policy.allow_implicit_invocation: false` in its `agents/openai.yaml`. This port is model-invocable, with a trigger-phrase-rich description. | Marketplace norm: pm skills are model-invocable so sibling skills can reach them — `pm:chart` routes a blocked ticket here by name, which an explicit-invocation-only skill cannot serve. The "never send it" rule below keeps the outward-facing act with the user, which is what the flag was protecting. |
| changed | **Output path.** Upstream writes `to-questionnaire-<slug>.md` in the current directory. A dropping of files into whatever cwd happens to be is the failure mode the convention exists to prevent. The fallback keeps upstream's behavior where the convention does not apply. |
| added | **Optional shared copy** — a Linear document when the recipient is a workspace collaborator, a vault note when the user keeps one.
