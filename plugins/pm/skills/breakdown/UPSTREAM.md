## Notes from the 2026-07-27 re-review (`d29732e49f60` → `ed37663cc5fb`)

Three upstream commits landed in this window. None was adopted; the reasoning is recorded here so future reviews don't re-derive it.

- **`44eed54` — one-file-per-ticket local tracker.** Restructured upstream's **local-files** path (single `tickets.md` → `.scratch/<slug>/issues/<NN>-<slug>.md`, plus `**Status:** ready-for-agent` in the template). Out of scope by an existing decision: `SKILL.md` ("Host follows fill") fixes the boundary at *an all-`.docs` breakdown has no skill — breakdown always publishes Linear children*. A `.docs/` **parent** is supported; `.docs/` **children** are not, so upstream's local-ticket file shape has nothing to map onto here.
- **`44eed54`, continued — the frontier promotion.** The same commit moved the frontier line **out of** the `<tickets-file-template>` block and **up into** tracker-agnostic body prose. This matters for applicability: at the previous pin the line lived inside a template this port doesn't use, so omitting it was not a divergence at all. Upstream's restructure converted it into an instruction that covers the real-tracker path too — which is what turned it into the ledger row above. Watch for this shape generally: **an upstream move from template text into body prose can create a divergence in this port without changing a word of the instruction.**
- **`ed37663` — removed "Work the frontier one ticket at a time with `/implement`, clearing context between tickets."** Silent on this port. Ours is step 8's *selective* spec-flow flag (only slices that warrant a contract), not a blanket implement-every-ticket handoff, so upstream retiring its own version neither obligates nor contradicts us.
