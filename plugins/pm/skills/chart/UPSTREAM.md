# Upstream divergences — chart

_Upstream: `mattpocock/skills` · `skills/engineering/wayfinder` · ledger current as of `reviewed_sha: 321658273cb1`_

Intentional divergences from upstream. First intake reviewed via `skillsmith:upstream-review` (2026-08-29) — do not re-flag these as findings. Read by `upstream-review` only; never referenced from `SKILL.md`.

**Prior partial adoption.** This marketplace already borrowed wayfinder's **fog of war** model before the skill itself was ported — the credit lives at `plugins/spec-flow/references/contract-template.md` (v2.2, "the idea only; no skill was ported"), and the model is live in `spec-flow:close`, `pm:breakdown`, and the `linear` skill. The intake therefore deliberately does **not** re-import the model; the skill cites the existing canonical definition instead. See the `changed` row on fog below.

| Kind | What | Why |
|------|------|-----|
| changed | **Name: `wayfinder` → `chart`.** The upstream path stays `skills/engineering/wayfinder`; only the local skill's identity changes. | `wayfinder` conflicts with an unrelated project, and a skill name that resolves to the wrong thing in the reader's head is a trigger bug. `chart` is the verb this skill's own body already ran on ("charts questions", "if charting surfaces no fog", "confirm the chart before publishing"), so the rename costs no new vocabulary, and it matches the one-word imperative every other pm skill uses. Upstream's own name survives wherever it names *upstream's* skill — the attribution row, and spec-flow's fog-of-war credit. |
| changed | **Invocation policy.** Upstream sets `disable-model-invocation: true` in frontmatter and `policy.allow_implicit_invocation: false` in its `agents/openai.yaml`. This port is model-invocable, with a trigger-phrase-rich description. | Marketplace norm: pm skills are model-invocable so sibling skills (`pm:breakdown`, `spec-flow:close`, `linear`) can reach them, and so a "this is too big to plan" phrasing routes without the user knowing the skill's name. The one-ticket-per-session rule and the explicit confirm-before-publish gate carry the restraint that upstream's flag was buying. |
| changed | **Fog-of-war model: cited, not restated.** Upstream defines the fog model inline (dim view, phrase-it-now test, graduation). This port states where fog lives at each stage and points at `plugins/spec-flow/references/contract-template.md` as the canonical definition. | The model was already adopted here from this same upstream skill, ahead of the skill itself, and is load-bearing in three other places. A second inline definition would be a fork of a shared model — the failure mode is silent drift between the two copies, not duplication per se. The port adds what the shared definition cannot know: the map-to-contract fog handover, so a patch lives in exactly one place across the whole chain. |
| added | **Fog hand-over on map close, and a close procedure at all.** Upstream's map ends when "no tickets remain"; it specifies no close step. This port adds one: still-fogged patches move to the successor contract's `## Not yet specified` or are ruled out of scope, then the map ticket completes. | Without it, fog is stranded on a closed map — the exact leak `spec-flow:close`'s drain gate exists to prevent one layer down. |
| changed | **Tracker is Linear, fixed.** Upstream is tracker-agnostic: it defers map/ticket/blocking/frontier mechanics to a per-repo "tracker doc", tells the user to run `/setup-matt-pocock-skills` if none was provided, and defaults to a local-markdown tracker. All of that is dropped; this port targets Linear via the `linear` plugin. | `setup-matt-pocock-skills` is bootstrap for upstream's own repo. This marketplace has exactly one tracker, and `pm:breakdown` already fixed the same boundary (it always publishes Linear children). A local-markdown fallback would be a second, unexercised code path. |
| changed | **Map identity: a `chart:map` marker label.** Upstream labels the map `wayfinder:map` and each ticket `wayfinder:<type>`. This port takes the map marker under our own skill name and drops the per-ticket prefix, carrying the ticket's mode in the body instead. | The marker was initially declined — `references/issue-shape.md` allowed exactly one surface + one type, so a third dimension was a workspace schema change rather than a skill's call — and was then adopted deliberately (2026-08-29) as an ungrouped marker additive to that pair, because maps are worth finding by query rather than by title search. The per-ticket prefix stays dropped: the `linear` skill's existing `Spike` / `Decision` / `Chore` taxonomy already types them, and a parallel vocabulary would hide map tickets from `pm:groom` and `pm:retro`. |
| changed | **Ticket types → the existing label set.** Upstream's four types map to labels this workspace already has: research → `Spike`, prototype → `Spike`, grilling → `Decision`, task → `Chore`. | The `linear` skill already owns this exact boundary (empirical vs judgment, hosted vs homeless) and its 2×2 puts an orphaned empirical unknown at `Spike` and an orphaned judgment unknown at `Decision`. A map ticket is orphaned by construction. Reusing the taxonomy means `pm:groom` and `pm:retro` see map tickets as ordinary tickets rather than a parallel vocabulary. |
| dropped | **HITL / AFK as labels.** Upstream makes every ticket explicitly HITL or AFK. This port keeps the *distinction* as prose (a "worked with the human" column, and the rule that the agent never stands in for the human's side) but adds no labels. | Consistent with the same drop already adjudicated for `pm:breakdown` ("HITL/AFK label split — considered and deferred, not adopted in this workspace's label set"). The behavioral half is load-bearing and was kept; only the label is dropped. |
| changed | **Skill dispatch re-routed to local equivalents.** Upstream calls the Skill tool with the bare strings `"grilling"`, `"domain-modeling"`, `"prototype"`, and `"research"` — its own repo's skills. Routed here to `craft:grill`, `craft:domain-modeling`, `craft:prototype`, and (for research) the built-in `Explore` agent or web research. `craft:grill-with-docs` is offered where the repo has a `CONTEXT.md` glossary or ndr coverage. | `craft:grill`, `craft:domain-modeling`, and `craft:prototype` are themselves adaptations of the upstream skills `wayfinder` names, so the routing is like-for-like. Upstream has no equivalent of `grill-with-docs`; that is a local addition. There is no local `research` skill, hence the agent-shaped substitute. |
| kept | **Ticket linking: the map's tickets are child issues of the map.** Upstream makes every ticket a **child issue** of the map. | `references/layer-policy.md` now adopts one level of native subissues (`parentId`) as the parent shape, so the port matches upstream. Native blocks / blocked-by between tickets is kept exactly as upstream has it, including its rationale (the frontier renders visually in the tracker UI). |
| added | **ndr routing.** Resolutions go to `Skill(ndr:capture-decision)`; the map's `## Decisions so far` row carries the returned `ndr:` reference; a grounding pass (`Skill(ndr:ground)`) runs before charting. Grounding first also stops the map charting a ticket for something a standing head already settled. `Spike` findings deliberately do **not** auto-capture — the `linear` skill's rule is that a finding becomes an atom only if it resolves a decision. |
| dropped | **Throwaway `research/<name>` branch for research findings.** Upstream captures each research subagent's findings on such a branch with a context pointer from the ticket. Here findings land as a resolution comment on the ticket (and a vault note where the `linear` skill's Spike rule calls for one). | A branch per research question is repo ceremony with no reader — Linear is where the map lives, and a comment is where every other resolution in this workspace goes. | added | **The handoff chain is stated explicitly** (`pm:chart` charts → `pm:breakdown` slices → spec-flow / clearance implements), with a boundary test ("can you already name the work, or only the questions?") and a stop-and-redirect when charting surfaces no fog. | Upstream has no sibling skill occupying breakdown's ground, so it never has to draw this line.
